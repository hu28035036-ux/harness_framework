# UI 디자인 가이드

## 디자인 원칙
1. 손님 웹은 탐색과 비교가 빠른 정보형 인터페이스로 만든다.
2. 기사 PC 프로그램은 작업 중 반복 사용을 고려해 조용하고 밀도 있는 도구형 인터페이스로 만든다.
3. 삭제, 취소, 중단, 최종 게시, 녹화 시작은 항상 명확한 경고 모달을 거친다.

## 레이아웃
- 웹 상단: 로고, 메인페이지, 기사목록, 기사구함, 사기꾼, 오류 및 건의사항, 설정.
- 우측: 손님/기사 모드 토글, 시스템/다크/화이트 테마, 로그인/프로필.
- 모바일: 하단 네비게이션 또는 햄버거 메뉴로 축약한다.
- PC 프로그램: 좌측 메뉴와 작업 상태 중심 대시보드를 기본으로 한다.

## 컴포넌트 기준
- 카드: 기사 카드, 홍보글, 인증게시글, 이전 작업물, 통계에만 사용한다.
- 상태 배지: 작성중, 업로드중, 게시완료, 평가대기, 업로드 실패, 복구 가능.
- 토글: 손님/기사 모드, 장시간 모드, 테마.
- 진행바: 클립 녹화, 업로드, 업데이트 다운로드.
- 필터칩: 직업, 사냥터, 인증방식, 평점, 상태.
- 미디어 뷰어: 캡처 확대, 30초 클립 재생, 추가 영상 재생.

## 금지 UI 패턴
- 장식용 그라데이션 오브, 글로우 애니메이션, 과도한 유리 효과를 사용하지 않는다.
- 기능 설명만 있는 랜딩 페이지를 첫 화면으로 만들지 않는다.
- 작업 도구 안에서 hero-scale 제목을 사용하지 않는다.
- 개인정보가 담긴 텍스트를 공개 카드, 툴팁, 로그에 노출하지 않는다.

## 테마
- 기본값은 시스템 모드다.
- 다크/화이트 모드는 웹과 PC 프로그램 모두 동일한 토큰 이름을 사용한다.
- 상태 색상은 의미 중심으로 사용하고, 단일 보라/파랑 계열로 화면 전체를 덮지 않는다.
